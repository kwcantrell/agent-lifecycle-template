# Panel: archived-task-edits

Tier: 2 · Reviewers: assumption tester (A), failure and abuse (F), scope and simplicity (S), each a separate Sonnet subagent · Date: 2026-09-29

Findings were de-duplicated across reviewers, and each id shows who raised it. The author reproduced both criticals before revising. Two findings went to the owner as decisions (S-3, F-4).

- [x] [critical] F-1 (F): `changed_files` splits git output on whitespace, so adding `<archive>/tasks.md smuggled.txt` next to a real `tasks.md` edit yields the tokens `<archive>/tasks.md` and `smuggled.txt`. The archive would look tasks-only, and the added file would be hidden. This is pre-existing and affects every gate. Evidence: temp repo, `.split()` of `git diff --name-only --cached main` -> `['.../tasks.md', '.../tasks.md', 'smuggled.txt']` (reproduced by the author). Resolved: design 1 (`-z` on every git call), spec requirement "Changed paths are read exactly", tests `test_path_with_space_read_whole` and `test_hidden_name_beside_tasks_counts`.
- [x] [critical] F-2 / A-1 (F, A): git rename detection lists only a rename's destination. Moving an archived `proposal.md` out while editing `tasks.md` would look tasks-only. Moving `tasks.md` away hides it entirely. This is pre-existing: `risk-floor` also misses high-risk files moved out of their directory. Evidence: `git mv <archive>/proposal.md moved.md`; `git diff --name-only main` -> `moved.md .../tasks.md`; with `--no-renames` -> also `.../proposal.md` (reproduced by the author). Resolved: design 1 (`--no-renames`) and design 2 (exemption computed from raw records), tests `test_rename_lists_both_sides`, `test_file_moved_out_of_archive_counts` and `test_tasks_added_deleted_moved_or_symlinked_counts`.
- [x] [major] F-3 / A-5 (F, A): "modified" was undefined. A symlink swap or mode change to `tasks.md` is listed by name only, so it would have been exempt, and `openspec validate` would then follow the link. Evidence: `git diff --raw` -> `:100644 120000 ... T .../tasks.md`. Resolved: design 2 requires exactly one `M` record with mode `100644` on both sides; the spec covers this; test `test_tasks_added_deleted_moved_or_symlinked_counts`.
- [x] [major] F-4 (F): a tier 0 PR can tick archived tasks that weren't done, or delete their `Evidence:` lines, and no gate checks it. Declined by human: the owner chose to document it as a residual (2026-09-29). The `change` message lists every exempted archive, CODEOWNERS covers `openspec/changes/`, and `docs/security.md` records the risk (design, "Owner decisions"; task 2.3).
- [x] [major] F-5 (F): a tasks-only edit to a grandfathered id's archive would skip the `Grandfathered:` declaration, and neither the spec nor the tests covered it. Resolved: design 5 (intended: exempt like any archive), spec scenario "Archive of a grandfathered id", test `test_grandfathered_archive_tasks_only_is_exempt`, and the `docs/security.md` wording update in task 2.3.
- [x] [major] S-1 (S): CODEOWNERS was cited as the control, but repos that keep their own CODEOWNERS may not cover `openspec/changes/`. Correction: this repo's `.github/CODEOWNERS` does list `/openspec/changes/` (`grep changes .github/CODEOWNERS`). Resolved: the design states the precondition, and notes that init prints the owned paths, `/openspec/changes/` included, for a kept CODEOWNERS (`scripts/lib/adopt.py:345`). The residual goes in `docs/security.md`.
- [x] [major] S-2 (S): AGENTS.md rule 10 requires an ADR for a new rule, and ADR 0014 is the precedent. Resolved: design 6, task 2.3 (`docs/decisions/0016-archived-task-edits.md`).
- [x] [major] S-3 (S): the open question (exempt edits versus skipping `--archived` for old archives) was unresolved in a proposal asking for approval. Resolved: the owner chose the hardened exemption on 2026-09-29 (proposal "Decisions"). The alternatives list now also covers "document a workaround".
- [x] [major] S-4 / A-2 (S, A): the note had to appear on every one of `check_change`'s eight return sites, but only PASS was specified and tested. Resolved: design 3 (a wrapper appends the note to any result), spec "Every `change` result (PASS, WARN or FAIL)", scenario "The note survives a failure", test `test_note_survives_failure`.
- [x] [minor] S-5 (S): the spec didn't restrict the exemption to archived directories, or say how renames are treated. Resolved: the spec names `openspec/changes/archive/<name>/`, requires the name form, and covers moves.
- [x] [minor] S-6 (S): missing tests for a mixed exempt and counted archive, a tier 1 PR body with only exempt edits, and tasks plus another file; tasks 2.1 and 2.2 didn't name their tests. Resolved: tasks 1.2-1.3 add them, 2.1-2.2 name their tests, and 2.3 states that docs need no test.
- [x] [minor] S-7 (S): the framing was overstated. Correction: autologger-2's ticks are on its unmerged install branch (`adopt-agent-lifecycle`), not on main. Resolved: Why now says no PR can carry the edit, and where autologger-2's edits sit.
- [x] [minor] F-6 (F): a real tier 0 code change paired with an archive tick is legitimate, since `risk-floor` still applies by path. The note must show on every stage. Resolved: design 3; all stages call the same function.
- [x] [minor] F-7 (F): shallow and no-base checkouts are conservative, and so is an old merge-base. Resolved: design 4, test `test_no_base_no_exemption`.
- [x] [minor] F-8 (F): archive names colliding with in-flight ids is not an issue. Resolved: pinned by test `test_moved_in_flight_change_plus_exempt_edit`.
- [x] [minor] F-9 (F): archive names printed in the message are attacker-controlled (for example workflow commands, newlines). Resolved: only names matching `YYYY-MM-DD-<lowercase id>` can be exempt, so printed names are safe (design 2 and 3).
- [x] [minor] A-3 (A): nothing parses the `change` message, so changing it is safe. Informational; recorded in the design's assumptions.
- [x] [minor] A-4 (A): the assumptions table lacked rows for `on_base` on directories and for rename behaviour. Resolved: rows added.
- [x] [minor] S-8 (S): size, structure and tier are fine, and nothing conflicts with "Tier 0 carries no change" or grandfathering. Informational.
